## 当前生产路线

```text
H3 Q4_0 + Turbo LoRA
  -> 两个长期 NCCL rank，QKV/FC1 column parallel，out/FC2 row parallel
  -> FP32 residual / attention output / NCCL，宽 Linear 使用 FP16 Tensor Core

Qwen3-VL-4B Q4_K_M + FP16 mmproj + mmh3-4b-ClipProj-v3.1 ridge
  -> direct-owner 4/32 layer MP，跨请求常驻，不重复 load/unload

Video VAE
  -> 12/24 decoder MP；INT8 ConvRot 使用 SM70 W8A16 临时 FP16 dequant
  -> spatial tile batch=2；输出按阶段转 CPU/磁盘，避免 GPU 留存 1.43 GiB
```

模型从 `/mnt/GALAX/minimax-h3/models` 读取；编译缓存、ComfyUI 输出和报告默认写到
`/home/regen`。大模型加载使用 header-only reader 与 4–8 MiB bounded staging，
禁止完整 payload host mmap 或完整 CPU 权重副本。服务仍由 RAM cgroup 保护：
`MemoryHigh=6500M`、`MemoryMax=7G`、`MemorySwapMax=256M`。

```text
H3_NO_HOST_MMAP=1
H3_VRAM_MODE=safe
H3_V100_ATTENTION=pytorch
H3_TP_COMPACT_QKV=q
H3_TP_COMPACT_QKV_MIN_SEQUENCE=4096
H3_TP_Q4_DEQUANT=eager
H3_QWEN_SPLIT=4             # direct Q4 GGUF owner split: 4/32
H3_FP32_RESIDUAL=1
H3_FP32_MLP=1
H3_FP32_MLP_CHUNK_ROWS=2048
H3_FP32_ATTN_OUT=1
H3_V100_FP32_TC=1
H3_TP_FUSED_FP32_OPS=1
H3_TP_FP32_OPS_WARPS=8
H3_TP_MLP_REDUCE_ROWS=8192
H3_VAE_SPLIT=24             # current service; historical 12/24 baseline below
H3_VAE_INT8_SM70_W8A16=1
H3_VAE_INT8_TILE_BATCH=2
H3_AUDIO_VAE_COMPILE=0
```

`H3_QWEN_SPLIT=4` 是 Q4 GGUF direct-owner 路径的默认语义；旧的 safetensors/INT8
layer-MP 对照仍使用历史 `12/24`，不要把两者混成一个全局切分规则。当前生产
`H3_VAE_SPLIT=24` 表示 VAE 的 `24/12` decoder split；设置为 `12` 可复现历史
`12/24` 基线。

这里的 VAE INT8 开关只在工作流选择 `minimax_h3_video_vae_int8_convrot.safetensors`
时生效；FP16 VAE 仍保留为回退选项。音频 compile 和其他 compile 路线均不属于默认。

注意 `H3_V100_RMS_ROPE` 的作用域：常驻 TP backbone 在自己的 block 路径中直接调用
已验收的 SM70 Q/K RMSNorm + partial RoPE，和这个环境变量无关；该变量只控制普通、
非 TP H3 fallback 的 monkey-patch，默认 `pytorch` 是兼容回退值。不要因为运行中的
普通 ComfyUI 环境变量显示 `H3_V100_RMS_ROPE=pytorch`，就误判 TP 路径没有使用
SM70 fused RMS/RoPE。

## 已通过的性能/精度结论

- Q-only layout 只复制 Q 为 contiguous BHSD，K/V 保持原 view，不改变 H3 global
  attention。完整 50 层 `S=37746` 从 `47.442 s` 降到 `44.051 s`，输出 SHA256
  完全一致，且 allocator reserve 没有增加；因此它是当前长序列默认。
- FP32 stability islands 不能删除。fused RMS/AdaLN、SwiGLU/scale 和 wide Linear
  已通过 finite、rank 一致性和成品 gate；纯 FP16 路径不作为性能基线。
- Qwen 生产使用 4B Q4 + ridge，而不是 27B/32B encoder，也不是 residual MLP
  projection。Q4 参考图 vision token 相对历史 INT8 baseline 的 relative RMS 为
  `17.94%`，这是已接受的显存/速度取舍，不宣称与 INT8/32B 数值等价。
- Q4/LoRA、Qwen 和 ClipProj 以 resident/direct-owner 路径跨请求复用；VAE 不能在
  目标尺寸采样峰值下与所有常驻模块永久共存，只在 decode 阶段使用。
- INT8 VAE 的 1 MP decode 为 `28.64 s`，相对 FP16 reference RMSE
  `0.00073252`、cosine `0.99999956`、全部 finite；12/24 split 和 tile batch=2
  已固定为当前候选路线。
- 已保存的最终 1 MP 无参考图基线为 `1344×768 / 124f / Turbo 4-step`：采样
  `196.464 s`、decode `60.15 s`、GPU 峰值约 `15870/14504 MiB`，latent/audio
  finite，模型跨请求不重载。首尾同图参考请求的旧 strided gate 也已保存。

## 明确不进入默认的实验

- 自定义 SM70 Triton global-attention：`S=2048` 约 `36 ms`，PyTorch efficient
  SDPA 约 `3.57 ms`；长序列也明显更慢，暂停。
- Triton Q4 直解：矩阵 microbenchmark 虽有约 `1.79–1.92x`，但完整目标长序列
  只有约 `0.9%` wall-time 收益，默认保持 eager。
- `torch.compile`/`max-autotune`：动态图、Q4 dequant、NCCL 和 shape 变化形成边界，
  当前完整路径收益不足且有冷编译成本；只保留音频 compile 的显式 opt-in。
- 全 Q/K/V compact、局部 `na3d`、Sage/FP8/NVFP4、普通 `device_map` 或
  DataParallel：要么增加显存、要么改变 H3 attention/TP 语义，均不接入生产。
